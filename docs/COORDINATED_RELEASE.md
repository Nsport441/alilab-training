# AliLab Training — انتشار هماهنگ Web و API

این فرآیند **دو سرویس Runflare را به یک سرویس تبدیل نمی‌کند**. هدف آن آماده‌سازی، آزمون و ردیابی **یک جفت بسته از یک Commit مشخص** است. مرحله استقرار Runflare هنوز دستی و نیازمند تأیید و کنترل مدیر است؛ هیچ API، وب‌هوک یا قابلیت انتخاب image digest در Runflare برای این پروژه تأیید نشده است.

## چه اتفاقی پس از ادغام در main می‌افتد؟

1. گردش‌کار `AliLab Phase 1A checks` همه آزمون‌های موجود را روی Commit ادغام‌شده اجرا می‌کند.
2. **فقط در صورت موفقیت آزمون‌های main**، گردش‌کار `Runflare build artifacts (no deploy)` خودکار فعال می‌شود. PRها نیز بسته آزمایشی تولید می‌کنند، اما این خروجی برای استقرار عملیاتی مجاز نیست.
3. هر دو ZIP از **همان SHA کامل** ساخته می‌شوند. هر کدام Dockerfile را در ریشه context مخصوص سرویس خود دارد؛ بنابراین خطای فقدان Dockerfile ریشه در روش ZIP رفع می‌شود.
4. هر دو image ساخته می‌شوند؛ Web از طریق proxy به API آزمایشی متصل می‌شود و health و corresponding source بررسی می‌شوند.
5. یک artifact با نام `runflare-<FULL_SHA>` شامل موارد زیر ذخیره می‌شود: `api-<SHA>.zip`، `web-<SHA>.zip`، `sources.json`، `images.jsonl`، `images.tar.gz`، `candidate.json` و `SHA256SUMS`. ماندگاری artifact در GitHub Actions برابر ۱۴ روز است.

با انتخاب دستی گردش‌کار از شاخه `main` نیز تنها زمانی بسته ساخته می‌شود که همان Commit آخرین نسخه main بوده و نتیجه کامل CI مربوط به آن موفق ثبت شده باشد. شروع این گردش‌کار **هیچ استقراری در Runflare انجام نمی‌دهد**.

## کنترل‌های قبل از استقرار

- آخرین بکاپ رمزگذاری‌شده و **آزمون بازیابی مستقل** را بررسی کن؛ کلید خصوصی را وارد GitHub یا چت نکن.
- از GitHub Actions، خروجی گردش‌کار مربوط به همان SHA را دریافت کن. فایل `candidate.json` باید `ciPassed: true` و `runflareDeployment: not_started` داشته باشد. این مقادیر وضعیت GitHub را نشان می‌دهند و اثبات انتشار نیستند.
- در پوشه خروجی، دستور `sha256sum -c SHA256SUMS` را اجرا کن؛ نام ZIP و SHA در `sources.json` باید با `candidate.json` برابر باشد.
- هویت imageهای CI در `images.jsonl`، digestهای قابل استقرار در registry نیستند. ZIP در Runflare دوباره ساخته می‌شود و لزوماً از نظر بایت با image آزمایش‌شده یکسان نخواهد بود.
- نسخه فعلی هر دو سرویس، تنظیمات شبکه/پروکسی و شناسه image فعلی را برای بازگشت اضطراری ثبت کن. دیسک متصل API و تنظیمات `DATA_DIR`، session، login و backup را دست نزن.

## انتشار کنترل‌شده در Runflare

1. اگر سازگاری نسخه جدید API با Web فعال و فرمت داده‌ها بررسی شده، **فقط ZIP داخلی** `api-<SHA>.zip` را برای سرویس فعلی `alilab-training-api` بارگذاری کن؛ آپلود طبق مستندات Runflare استقرار را شروع می‌کند. ZIP باید Dockerfile را در ریشه داشته باشد.
2. صبر نکن تا صرفاً وضعیت «Running» نمایش داده شود؛ از طریق مسیر واقعی proxy موجود، `/api/health`، ورود با رمز، خواندن داده موجود و یک عملیات خواندن/نوشتن غیرمخرب را بررسی کن. پورت خصوصی API و دیسک پایدار باید قبلی باقی بمانند.
3. سپس `web-<SHA>.zip` را فقط برای `alilab-training-web` بارگذاری کن. `BACKEND`، `PORT`، `RESOLVER`، `NGINX_PORT` و ارتباط شبکه داخلی باید از تنظیمات **واقعی فعلی Runflare** حفظ شوند؛ پیش‌فرض‌های Docker Compose لزوماً در Runflare صحیح نیستند.
4. از آدرس عمومی `https://training.alilab.ir/` و `/api/health`، عملکرد ورود، مدیریت، ثبت تمرین و دریافت داده را بررسی کن. تطبیق commit مستقر فقط با شواهد معتبر Runflare/اطلاعات runtime انجام شود، نه صرفاً version یا تاریخ image.
5. زمان و وضعیت واقعی هر سرویس، SHA و شناسه image را ثبت کن. برای پنل «مدیریت نسخه‌ها و انتشار»، تنها در صورت داشتن مدرک معتبر می‌توان فایل شواهد `RELEASE_EVIDENCE_FILE` را با روال امن `docs/RUNFLARE.md` تهیه کرد.

**دو سرویس یک استقرار اتمیک ندارند.** اگر API ناسازگار یا ناسالم باشد، Web را مستقر نکن. «Revert» در Runflare پیش‌نمایش نیست و خودش استقرار جدید انجام می‌دهد؛ بازگشت به image قدیمی هم داده‌های پایدار را برنمی‌گرداند. در صورت خطا، پیش از هر rollback سازگاری داده و نسخه و برنامه بازیابی را بررسی کن.

## محدودیت فعلی و مسیر تکمیل خودکارسازی

در این PR **فقط آماده‌سازی و تأیید یکپارچه در GitHub** خودکار می‌شود. فعال‌سازی Auto Pull، جابه‌جایی branchها، انتشار registry image یا استقرار Runflare انجام نمی‌شود. برای تبدیل مرحله آخر به یک دکمه «انتشار» باید Runflare رسماً یکی از روش‌های قابل کنترل استقرار از یک SHA/digest، استقرار مرحله‌ای و مشاهده وضعیت/سلامت را ارائه دهد. تا آن زمان از وب‌هوک یا endpoint حدسی و از تغییر خودکار دو سرویس تولیدی استفاده نکن.
