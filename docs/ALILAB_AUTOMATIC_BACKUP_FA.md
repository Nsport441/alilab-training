# بک‌آپ رمزنگاری‌شدهٔ روزانه با n8n

این قابلیت پیش‌فرض خاموش است. ساخت این فایل‌ها یا import کردن ورک‌فلو به معنی فعال‌شدن
بک‌آپ روزانه نیست. مسیر `POST /api/ops/backup` فقط یک آرشیو رمزنگاری‌شده می‌دهد؛ توکن آن
به ورود، مشاهدهٔ حساب، ویرایش تمرین یا بازیابی روی سرور دسترسی نمی‌دهد.

## محدودهٔ سازگاری snapshot

نسخهٔ آزمایشی AliLab فقط یک فرایند نویسندهٔ API با Coach و آپلود خاموش دارد. در این حالت
خواندن همهٔ فایل‌ها به‌صورت **همگام در همان event loop API** انجام می‌شود؛ هیچ handler یا timer
همان فرایند در میانهٔ خواندن اجرا نمی‌شود. این مسیر به توقف روزانهٔ سرویس نیاز ندارد، اما
خواندن کوچک فایل‌ها event loop را موقتاً نگه می‌دارد. محدودیت سخت: ۱۶ MiB داده و ۵۱۲ فایل.
فایل‌های root شامل `db.json` و `secret` لازم‌اند؛ symlink و فایل ویژه رد می‌شوند. پوشهٔ root
`.alilab-backups` کنار گذاشته می‌شود. نام فایل‌ها و checksumهای manifest داخل رمزنگاری‌اند.

این روش writerهای دیگر را متوقف نمی‌کند. `ALILAB_BACKUP_SINGLE_WRITER=1` صرفاً تأیید صریح
اپراتور دربارهٔ معماری است، نه قفل توزیع‌شده. فقط یک replica، بدون writer خارجی و بدون
هم‌پوشانی استقرار مجاز است. هنگام استقرار/نگهداری، اجرای ورک‌فلو متوقف شود و طبق راهنمای
عملیات، نبود نویسندهٔ قبلی تأیید شود. با افزایش داده، فعال‌شدن media یا Coach، چند replica یا
writer خارجی، این مسیر نباید فعال بماند؛ به snapshot هماهنگ با writer یا پایگاه داده نیاز است.

## کلید و دسترسی محدود

برای هر آرشیو یک کلید AES-256-GCM تصادفی ساخته می‌شود. این کلید با RSA-OAEP-SHA256 به
کلید عمومی مالک رمز می‌شود و همراه ciphertext در فایل `.alilab` قرار می‌گیرد. کلید خصوصی
RSA خارج از Runflare، n8n، GitHub و پوشهٔ Drive باقی می‌ماند. کلید خصوصی برای بازیابی لازم است؛
بستهٔ بازیابی این نسخه با بستهٔ کلید AES بک‌آپ دستی ۱۵ اکتبر تفاوت دارد. قبل از فعال‌سازی،
بستهٔ جدید باید دانلود و جدا نگه‌داری شود.

توکن بک‌آپ ۳۲ بایت تصادفی با نمایش ۶۴ حرف hex است. فقط SHA-256 متن توکن روی API قرار
می‌گیرد؛ مقدار خام فقط در Credential اختصاصی n8n نگه‌داری می‌شود. توکن، کلید و env واقعی
نباید در سورس، Workflow JSON، URL، پین‌دیتا، log یا توضیح PR قرار گیرند. درخواست بدون توکن
صحیح 401 است؛ حالت خاموش 404. پس از یک export موفق، درخواست بعدی تا یک ساعت 429 می‌گیرد؛
این شمارنده در حافظه است و با restart بازنشانی می‌شود. پاسخ `no-store` است.

## تنظیمات پس از تأیید فعال‌سازی

```text
ALILAB_BACKUP_ENABLED=1
ALILAB_BACKUP_SINGLE_WRITER=1
ALILAB_BACKUP_TOKEN_SHA256=<sha256-of-token-text>
ALILAB_BACKUP_PUBLIC_KEY=<RSA-public-PEM-at-least-3072-bits>
COACH_DISABLED=1
MEDIA_UPLOADS=0
```

PEM می‌تواند newline واقعی یا `\n` داشته باشد. پیکربندی ناقص در حالت فعال، startup را رد
می‌کند؛ ابتدا همهٔ مقادیر آماده و صحت آن‌ها بررسی شود. فعال‌سازی API باید با روش ایمن
توقف/شروع سرویس انجام شود تا دو writer هم‌زمان ساخته نشوند.

## ورک‌فلو

فایل `ops/n8n/alilab-training-encrypted-drive-backup.json` با وضعیت غیرفعال import شود.
در قالب عمومی، `REPLACE_DRIVE_FOLDER_ID` و `REPLACE_BACKUP_PUBLIC_KEY_ID` باید با مقصد و
شناسهٔ کلید عمومی همان استقرار جایگزین شوند؛ نسخهٔ تنظیم‌شدهٔ مالک جداگانه ارائه می‌شود.

1. Credential نوع Header Auth با نام `AliLab Training Backup`: نام header برابر
   `Authorization` و مقدار آن `Bearer <raw-token>` باشد.
2. برای دو نود Google Drive اتصال موجود `n8n Google Drive` انتخاب شود. مقصد، پوشهٔ خصوصی
   انتخاب‌شدهٔ مالک است. هیچ اشتراک یا لینک عمومی ساخته نمی‌شود.
3. ساعت پیشنهادی ۰۳:۳۰ با timezone `Asia/Tehran` است؛ پیش از Publish بررسی شود.
4. نود Check envelope فرمت و شناسهٔ کلید عمومی را بررسی می‌کند؛ سپس آرشیو به Drive می‌رود.
   فایل از همان file ID دوباره دانلود و تمام بایت‌ها با خروجی اولیه مقایسه می‌شوند.
   نتیجهٔ متفاوت اجرای n8n را Failed می‌کند.
5. اجرای دستی واقعی باید پس از استقرار/فعال‌سازی موفق شود. سپس همان فایل Drive با کلید
   خصوصی در مسیر مستقل بازیابی و checksumها بررسی شوند؛ پس از این آزمون ورک‌فلو Publish شود.

اعداد تولیدشده در این JSON، کلید خصوصی یا توکن واقعی نیستند. شناسهٔ کلید عمومی باید با
کلید تنظیم‌شده روی سرور و بستهٔ خصوصی مالک برابر باشد. ورک‌فلوهای دیگر و credentialهای
آن‌ها تغییر نمی‌کنند. موفقیت اجرا ذخیره نمی‌شود؛ خطاها در Executions ثبت می‌شوند و ممکن است
حاوی خود آرشیو رمزنگاری‌شده باشند. فایل‌های قبلی خودکار حذف نمی‌شوند؛ در این مرحله سیاست
حذف یا اعلان Telegram ساخته نشده است.

## بازیابی آفلاین

با Node.js 22 یا جدیدتر، در یک پوشهٔ خالی و مستقل:

```sh
chmod 600 recovery-private.pem
node scripts/alilab-restore-sealed-backup.mjs backup.alilab restored recovery-private.pem --api-stopped
```

ابزار فرمت envelope، شناسهٔ کلید، اصالت AES-GCM و checksum تک‌تک فایل‌های بازیابی را بررسی
می‌کند. مقصد پر بازنویسی نمی‌شود. این دستور API را متوقف نمی‌کند؛ برای جایگزینی دادهٔ زنده،
اول نویسنده‌ها واقعاً متوقف شوند. رمزنگاری، منشأ یک فایل ناشناس را اثبات نمی‌کند؛ فقط آرشیو
دریافت‌شده از سرور/Drive معتبر خودتان را با رسید تطبیق دهید.
